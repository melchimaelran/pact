# State Model — the single source of truth

## The rule

**One writable source of truth per story: its file's YAML frontmatter.** Every
index (`STORIES_INDEX.md`, `FEATURE_INDEX.md`, `docs/decisions/README.md`) is a
**generated, read-only view**, produced by `scripts/views.sh` from frontmatter. A
view is a pure function of the frontmatter, so it cannot drift. There is no
reconciler. To change state, a command edits frontmatter and regenerates.

## Spec frontmatter

`docs/specs/YYYY-MM-DD_<slug>/spec.md`

```yaml
---
id: SP-NNN                 # sequential, project-wide
type: feat                 # feat | fix | adjust | refactor | perf | chore | docs
slug: <kebab>
status: draft              # draft -> ready -> planned -> done
created: YYYY-MM-DD
charter_version: X.Y.Z     # the constitution version this spec was written against
depends_on: []             # other spec ids that must be `done` before this one builds
target: ""                 # adjust/refactor/perf: the spec id or feature slug changed
security: false            # true when produced by `pact security`
---
```

`status`:

- `draft` — being written / clarified.
- `ready` — approved by the user; `plan` may consume it.
- `planned` — `plan` has produced epics/stories under `tasks/`.
- `done` — merged to the target branch.

## Story frontmatter

`tasks/YYYY-MM-DD_<slug>/epics/<NN>_<epic>/stories/<NN>_<story>.md`

```yaml
---
id: 01-02                  # <epic>-<story>, unique across the whole project
title: Contact form component
epic: 01
spec: SP-003
type: feat                 # inherited from the spec
status: todo               # todo -> in-progress -> done  (+ skip, bug)
delivery: ""               # "" -> pr -> merged   (or "direct")
blocked_by: []             # ["01-01", …] story ids in the same plan
prior_status: ""           # the status before it became `bug`
issue: ""                  # GitHub issue number when issue_tracking is on
pr: ""                     # PR number after ship
---
```

Body sections: `## Goal` · `## Acceptance Criteria` (checkboxes, a subset of / a
refinement of the spec's AC) · `## Implementation Tasks` (short ordered checklist,
non-binding) · `## Notes`.

There is **no `size:` field** — a story is "one vertical behavior, testable on its
own, that one agent finishes in one pass". There is **no `files:` field** — wave
planning uses `blocked_by` alone; file conflicts are handled at the rehearsal
merge (see [`wave-orchestration.md`](wave-orchestration.md)).

## The two axes

| Axis | Values | Meaning |
|---|---|---|
| `status` | `todo -> in-progress -> done` (+ `skip`, `bug`) | the work itself |
| `delivery` | `"" -> pr -> merged` (or `direct`) | how far it travelled toward the trunk |

"Done" and "shipped" are different facts. A story can be `done` with no PR, `done`
with an open PR, or `done` and merged. `blocked_by` resolves against
`status: done` only — never against `delivery`.

Bug flow: `done -> bug` (set by `fix`, previous status recorded in `prior_status`)
`-> done` (restored by `build` bug-fix mode when the recorded fix lands).

## Generated views

Regenerated by `scripts/views.sh`, never hand-edited:

| View | Content |
|---|---|
| `tasks/<slug>/STORIES_INDEX.md` | one row per story: id, title, epic, status, delivery, blocked_by |
| `tasks/FEATURE_INDEX.md` | one row per spec across all plans: id, slug, type, epics done/total, stories done/total, delivery |
| `docs/decisions/README.md` | DR table: id, title, kind, status, date |
| `tasks/ROADMAP.md` | only when `pact status --write` is run — a generated snapshot |

`pact status` renders the same picture live from frontmatter without touching a
file.

## Regeneration cadence

- `plan` — once, after writing the story files.
- `build` — once per wave (after the wave settles), and once on every `build` exit
  (success or clean interrupt). Never per story.
- `ship` — once, post-merge (delivery updates).
- `migrate` — once, after the layout conversion.

`pact check` flags a view that has drifted from frontmatter (should never happen
outside a crash mid-write).
